# Арт: формат описаний

> Формат `tools/art/generate.py`, перенесён из [I love Kuni](https://github.com/Alex2772/i-love-kuni) как есть.
> Разделы «Опыт» — реальные поломки из той игры: имён файлов оттуда здесь нет, но уроки те же. Пример файла
> описаний — [`example.md`](example.md).

В коде у картинки есть только id: `KN_IMAGE(prologue, room);` → `img::prologue::room`. Промпт, генератор и разметка
лежат здесь, по файлу на акт (`prologue.md`, `act1.md`, …). Файл дока — это папка: `### room` в `prologue.md` имеет id
`prologue/room` и лежит в `data/img/prologue/room.webp` (вспомогательные — в `art/base/prologue/`). Внутри дока
в `edit`/`refs` пишется короткое имя (`room`), картинку другого акта называют полным id (`prologue/room`). `tools/art/generate.py` читает эти файлы и генерит картинки.

```
## Общее
- define HIM: 1boy solo, ...           подстановка {HIM} в любом prompt этого файла

### room                               имя KN_IMAGE (без папки) или вспомогательной картинки
- gen: sdxl, 1216x832, seed 3473       локальный SDXL (размер и seed обязательны)
- gen: sdxl cutout, 832x1216, seed 1   то же, белый фон вырезается в альфу
- gen: edit room_base                  правка другой картинки через OpenRouter (gemini), размер берётся у исходной;
                                       `edit X cutout` — потом вырезать белый фон
- gen: ref, 1216x832                   новая картинка через gemini только по референсам (`refs` обязательны)
- gen: text, 1024x1024                 gemini только по промпту, без картинок: текстуры миниигр (`race.md`), не панели;
                                       размер — степень двойки (WebGL 1: повтор и mipmap только у таких)
- gen: closeup room 0.40 0.30 0.25 0.30  крупный план куска другой картинки (x y w h в долях): кусок вырезается,
                                       растягивается до 1K и перерисуется gemini резким; `prompt` — что в куске (или
                                       «the same as the first image»). Для панелей с большим zoom (ArtDensityTest);
                                       блоки и новые focus/zoom считает `tools/art/closeup_plan.py`
- refs: room desk face                 референсы для `edit` и `ref`: стиль, персонаж, предметы, которые должны
                                       совпасть; уходят в gemini после правимой картинки
- prompt: ...
- negative: veins, bed                 только sdxl: чего не должно быть, дописывается к стандартному негативу
- avoid: 0.30 0.05 0.40 0.60; ...      что пузыри не должны закрывать: x y w h в долях картинки (лицо, кот, текст)
- he: 0.47 0.28                        точка головы персонажа (id из Cast.h) — туда тянется хвостик его реплик
- purpose: зачем читателю эта панель  свободный текст; обязателен для картинок с focus-линиями (`--lint`)
- shows: открытый рот; пластиковая вилка  что обязано быть видно в кадре (по тексту панелей); `--lint` сверяет
                                       с репликами, `--review ID` печатает чек-лист самопроверки; в spec не входит
- time: morning                        свет в кадре: morning|day|evening|night|none (none = света нет: белая комната,
                                       страница крупно); обязателен у каждой картинки из story/src
                                       (EveryUsedPictureSaysItsTimeOfDay, долг story/tests/untimed_art_debt.txt);
                                       читает ArtContinuityTest (смена светлого на тёмное в файле сцены — только после
                                       текста про время суток; текст со временем — на картинке того же света)
- has: cat                             что нарисовано в кадре и важно для непрерывности (cat); читает ArtContinuityTest
- needs: deck                          картинка показывает то, что вводит более ранняя панель той же сцены (имя
                                       картинки); использовать её раньше нельзя; читает ArtContinuityTest
- screen: 0.19 0.16 0.66 0.67 [-28]    экран монитора/телефона: x y w h в долях картинки, угол в градусах;
                                       текст на нём рисует движок (`screen()` в сценарии)
```

## Канон: референсы персонажей и мест

Соседние картинки обязаны состыковываться: окно, камин, дверь, лестница стоят на тех же местах, персонаж выглядит
одинаково. Поэтому у каждого персонажа и у каждого места есть **канонический референс**, и каждая картинка с ними
строится от него.

- **Персонажи** — `docs/characters/<id>/README.md`, раздел `## Референсы`: какие файлы канон и для чего (лицо,
  полный рост, одежда по главам). Новый персонаж сначала получает референс (и раздел в README), а
  уже потом первую панель.
- **Места** — `docs/locations/<место>/README.md`: план (что на какой стене, где окна и двери, откуда свет), список
  ракурсов и референсные картинки. Пример — `docs/locations/kitchen/`.
- **Как ссылаться:** в `refs` можно писать путь к файлу от корня репо:
  `- refs: docs/locations/mansion/dining.webp docs/characters/kuni/kuni-maid.png`. Файл берётся как есть.
- **Любая картинка с персонажем или в известном месте** делается через `gen: ref` или `edit` с этими референсами в
  `refs` (SDXL референсов не видит). В промпте прямо назови, что должно совпасть: «the same dining room as in the
  second image: the tall windows are on the left wall, the fireplace on the far wall».
- Перед новой картинкой открой README места и сверь ракурс с планом: если камера смотрит на северную стену, окон там
  нет — значит, и на картинке их нет.
- Нужен ракурс или место, которого нет в `docs/locations/`, — сначала допиши план и референс туда, потом панель.
- **Косяки на готовых картинках правятся только через OpenRouter** (`gen: edit` в этом формате или скилл
  `openrouter-image`), а не перегенерацией SDXL с нуля и не ручной правкой пикселей.

## Правила

- **Не рисовать в высоком разрешении. Максимум 1K** (длинная сторона ≤ ~1216 px, как в базовом `gen: sdxl`).
  Решение автора (2026-11-09). ⚠ Сейчас этому противоречат `tools/art/generate.py` (gemini зовётся с
  `--size 2K`, SDXL с `--hr`) и пункт про `--hr` ниже в «Как работать»: не правила, жду ок автора.
- **Текста на картинках нет.** Экраны, телефоны, записки рисуются пустыми, текст поверх рисует движок: так его
  можно перевести. Исключение — то, что не зависит от языка (цифры на часах).
- **SDXL** — основа всего. Текст SDXL не умеет.
- **Между панелями ничего не различается.** Стол, клавиатура, монитор, часы на руке, кот — один и тот же предмет на
  всех картинках, где он виден. Читатель листает страницу, и другая клава на соседней панели — это уже другая
  комната. Если предмет есть на уже принятой картинке, передай её в `refs` и прямо напиши в промпте: «exactly the
  same keyboard as in the second image: model, colour, key layout, size». Пример: `hands` → клава в `monitor`.
- **Руки, крупные предметы, сложная анатомия — через `gen: ref`, а не SDXL.** SDXL в аниме-модели ломает пальцы
  (переплетённые, шестой палец, «вены» как сопли), ставит клавиатуру торцом, рисует системник как чемодан, а hires-проход
  ломает то, что было нормальным в превью. Gemini по референсам из уже принятого арта держит стиль и анатомию.
  Порядок: 3–4 варианта одним промптом в scratchpad → автор выбирает → положить выбранный в `data/img/<id>.webp`
  (cover-fit под размер из `gen`) → `--adopt <id>` → размечать `avoid`.
- **Картинки gemini не воспроизводятся**: сида нет, перегенерация даёт другую картинку. Поэтому изменившийся
  референс не делает картинку устаревшей; `--list` только пишет `remade after it: …`. Перегенерируй её явно по id и
  снова выбери, если она должна совпасть с новым референсом.
- **Правка не должна двигать то, что размечено.** Чтобы поменять одну деталь на картинке с `screen`, правь
  готовую картинку (`edit <она же>_clean`, исходник — в `art/base/`), а не переделывай цепочку с нуля. После правки
  перемерь `screen`/`avoid`: gemini может слегка сжать или сдвинуть монитор (так было с `monitor`).
- **edit** — точечные правки: сделать кота бенгальским, очистить экран от мусорного текста SDXL.
  Исходник — SDXL-картинка, поэтому стиль не плывёт. В промпт правки добавляй `{EDIT_STYLE}`: «оставь стиль и
  композицию, поменяй только …».
- **Вспомогательные картинки** (id, которого нет в коде, например `room_base`) кладутся в `art/base/<акт>/`, а не в
  `data/img/`, и в игру не попадают.
- `avoid` и точки голов скрипт пишет в `data/img/<id>.json`; движок по ним расставляет пузыри. Размечай каждую
  картинку, которая идёт в игру: посмотри на неё и запиши лица, важные предметы и текст на экране.

```bash
python3 -I tools/art/generate.py --list            # статус: ok / STALE / missing
python3 -I tools/art/generate.py                   # сгенерить всё устаревшее (и обновить разметку)
python3 -I tools/art/generate.py prologue/cat prologue/room   # перегенерить эти
python3 -I tools/art/generate.py --adopt prologue/city     # принять уже лежащий файл как соответствующий описанию
```

SDXL работает локально (`localhost:7860`), OpenRouter — по ключу `OPENROUTER_API_KEY`. В окружении есть
`HTTP_PROXY`: скрипт сам ставит `no_proxy` для localhost.

## Панель с объектом внимания

Каждая панель имеет назначение (`- purpose:` — что показывает и зачем читателю); объект внимания целиком в кадре,
не по центру, с focus-линиями; реплика-реакция ниже-левее объекта. Подробно и на примере `inv1/mirror_door`:
`docs/STORY_API.md`, «Панель с объектом внимания». `--lint` требует `purpose` у картинок с focus/speed-линиями.

## Самопроверка (перед тем как отдать картинку)

`tools/art/generate.py --review ID` печатает чек-лист для картинки, `--lint [ID…]` сверяет `- shows:` с текстом
сценария (статически, по `story/src`) и ругается на фразы из `- ban:` ниже. Каждой сгенерированной панели:

1. **Буква реплики.** Открытый/закрытый рот, что в руках, куда смотрит, эмоция: названное в тексте видно на кропе.
   Gemini рисует спящих и молчащих с закрытым ртом, пока не написано «mouth OPEN»; промпт — намерение, а не результат.
2. **Реквизит по ситуации.** Доставка еды: одноразовая белая пластиковая вилка, чёрный пластиковый лоток, бумажный
   пакет с ручками. Не металл. Слова «plastic fork» мало: «chunky opaque milky-white plastic, broad flat thick
   handle, short thick blunt tines».
3. **Одежда по канону.** Сверь с `docs/characters/*/README.md`: длина рукава до запястья/ладони у людей; у Куни **короткие
   пышные чёрные рукава-фонарики у плеч с белой оборкой**, предплечья, запястья и кисти голые, манжет нет (`kuni-maid.png`).
   На кропе проверь: оборка только у плеча, ниже голая кожа, без манжет, рубашки и блузки. Пиши именно так:
   «short puffed black sleeves ending at the upper arm with a small white frill, bare forearms, no cuffs».

4. **Соседние панели — разные кадры.** Две панели подряд не показывают одну и ту же картинку и не спорят по времени
   суток (ночные часы рядом с утренним котом — «странные две панели», баг `ch1/Clock`). Нужен другой ракурс/крупность,
   единое освещение.
5. **Двухшаговая сборка.** Если `gen: ref` с людьми двигает фон (мелкие предметы уезжают на передний план), делай
   пустую комнату `*_clean` (меняется только свет) и потом `edit` с людьми.

6. **Сквозной предмет — канон, как у персонажей.** Предмет, который появляется на многих панелях (Оракул), имеет
   папку `docs/props/<предмет>/` с README и референсом, и `refs:` на него в каждой панели. Иначе каждая панель
   рисует свой вариант (у Оракула были купол и безымянная щель).
7. **Предмет физически пригоден к глаголу в реплике.** Бумажку нельзя вставить в щель сквозь стекло: сверяй
   рисунок с действием из текста.
8. **У каждой функциональной детали есть назначение.** Щель, кнопка, отверстие описаны в README предмета, иначе
   читатель выдумывает своё («монетоприёмник»).
9. **Дубли предмета.** Gemini при `gen: ref`/edit любит дорисовать второй экземпляр и переставить рычаг на другую
   стенку: пиши «exactly ONE machine» и смотри кадр глазами.

- ban: white cuff → манжета/полоска кожи у кисти; у Куни пиши «bare forearms, no cuffs»

## Что работает (подтверждено пользователем)

Комнаты получаются одинаковыми и согласованными между условиями, временем суток и персонажами: подход с
референсами мест (`docs/locations`, `refs:` на эталон комнаты, двухшаговая сборка «пустая комната → edit с людьми»)
держим как есть и не ломаем.

## Опыт: на чём арт уже ломался

Замечания автора к готовому арту и что с ними сработало. Перед тем как отдавать картинку, проверь её по этому списку.

**Что ловит автор** (смотри на картинку его глазами, а не «в целом похоже»):

- **Текст панели виден на картинке.** Прочти реплики всех панелей, где стоит картинка (`grep -rn '<id>' story/src`),
  и проверь, что каждое названное действие и предмет есть в кадре и в кропе панели. `hand_hover`: подпись «он
  укрывает её пледом», а плед лежал на подлокотнике; промпт про «covers her up to the shoulders» был, но gemini его
  не выполнил, и никто не посмотрел. `dining`/`eat`: в 1.6 «ноутбук остался на столе в столовой», а на столе в
  столовой ноутбука не было ни разу. Промпт — это намерение, проверяется картинка.
- **Отсылка к прошлому — это реквизит прошлых панелей.** Если позже текст ссылается на предмет («остался на столе»,
  «та же кружка»), он должен быть на ранней картинке в том же месте. Добавляя такую строку, допиши предмет в промпт
  ранних картинок или поправь их через `edit`, и тот же предмет по месту и виду на соседних кадрах.

- **Место действия.** Будильник «на столе» SDXL поставил на кровать с простынёй, а на фоне нарисовал второй будильник
  (`clock`). Предмет должен стоять там, где он стоит по сюжету, и быть в кадре один. Помогает назвать соседние
  предметы («edge of a keyboard and a monitor stand next to it») и запретить лишнее в `negative` («bed, bedsheets,
  (second clock, multiple clocks:1.4)»).
- **Предмет читается как он сам.** «Игровой ПК» у SDXL выходил чемоданом с глазом, колонкой или сай-фай колонной
  (`fans`), и никакие промпты не помогли. Сработало так: SDXL-основа с нужной композицией, а потом `edit` в gemini с
  подробным описанием («motherboard, RAM, CPU cooler, graphics card, three case fans… it must clearly read as a real
  desktop computer, not a speaker or a box»).
- **Анатомия.** Пальцы считай: по пять на каждой руке, не переплетены, нет лишнего сустава. Вены у SDXL похожи на
  сопли, поэтому их не рисуем совсем («no visible veins», в SDXL ещё и `negative: (veins:1.5)`).
- **Геометрия предметов.** Клавиатура лежит на столе плашмя, клавиши обычные и на равных расстояниях. Клава
  «торцом», «перпендикулярно» или с кашей мелких клавиш = брак.
- **Приметы персонажа на каждой картинке.** У Папика серебряные часы на левой руке и золотой браслет на правой
  (`HIM` в `prologue.md`). SDXL часто делает часы золотыми или путает руки (`head_down`, `hands`). Когда в кадре
  персонаж, сверяй часы, браслет, цепочку, причёску и цвет волос (тёмно-каштановые, не чёрные).
- **Левая/правая рука.** Для кадров с одной его рукой в промпте указывай, какая это рука (канон: левая — серебряные часы, правая — тонкая золотая цепочка), и проверяй на кропе большой палец и аксессуар. Куни украшений на руках не носит (`ch5/one_bowl`: часы оказались на правой руке Папика).
- **Приметы должны попасть в кадр панели**, а не только на картинку. В `room` часы были на левом запястье у
  нижнего края, а широкая панель 1×0.3 показывала только ~2/3 высоты, и в кадре остался один золотой браслет.
  Видимая доля высоты картинки = (высота панели × 1.5 / ширина панели) × (ширина картинки / высота): посчитай и
  подбери `.focus`/высоту панели, чтобы лицо и часы влезли.
- **Лишние предметы у края кадра.** Gemini при `edit` дорисовал за стулом сай-фай панель с золотом (`room`).
  Убрали отдельной правкой готовой картинки (`room` ← `edit room_clean`): назвать предмет и место, сказать,
  что на его месте («just the dark wall of the room with a few cables»), и перечислить, что оставить.
- **Мусорный текст SDXL** на мониторах («LENCET») тоже брак: убери его правкой или закрой `screen`.
- **Предмет не похож на чужого персонажа.** «Будильник» SDXL нарисовал круглым корпусом с двумя «ушами» и светящимся
  ободом, и вышел робот Зурк из Stray (`clock`). Милый «живой» предмет — брак, даже если сам по себе он красивый.
  Помогла переделка через `gen: ref` в gemini (референсы `desk room`) с прямыми запретами: «a plain, ordinary,
  cheap … a simple flat rectangular box … No ears, no bells, no round body, no face, no eyes, not a robot, not cute,
  nothing character-like». У бытовых предметов называй скучную форму («rectangular plastic box»), а не просто тип.

- **Глаза Папика карие** (`HIM` в промптах уже говорит «brown eyes», но gemini рисует серо-зелёные: `cs_corner`).
  Смотри на кропе цвет радужки, не верь промпту; чинится `edit` с «warm dark brown (hazel-brown) irises, not grey, not green».
  Зелёные глаза только у кота.
- **Картинка не показывает то, что ещё не случилось.** `group` (все на ковре с картами) стояла в 2.5 «Пятница» на
  «Барсук вбивает в ноут», а колоду находят позже, в 2.6: читатель видел карты раньше текста. Если картинка несёт
  предмет/персонажа/состояние, которое вводит более поздняя сцена, ей ставят `- needs: <картинка, где это вводится>`,
  а для ранней сцены делают свою картинку (`friday_laptop`). Охраняет `story/tests/ArtContinuityTest.cpp`
  (`PictureDoesNotShowWhatIsIntroducedLater`).
- **Появившийся позже не стоит в кадре раньше.** `ch4/fireplace` (Куня сушит волосы у камина) шла на панелях «Вечер»
  и «он садится у камина» раньше фразы «Куня выходит из душа». Три кадра: пустая гостиная (`fireplace_empty`), он один
  (`fireplace_papik`), потом она (`fireplace`, `- needs: fireplace_papik`). Охраняет тот же `PictureDoesNotShowWhatIsIntroducedLater`.
- **Крупный план — своя картинка, не zoom общего.** `ch1/kitchen_maid` (1216×832) на zoom 3.57 на MacBook во весь
  экран — мозаика: пиксель арта ≈ 7×7 пикселей экрана. Порог плотности, как его считать и как чинить (крупный план
  отдельной картинкой через openrouter или вся картинка в разрешении повыше) — в `story/tests/ArtDensityTest.cpp`,
  долг в `story/tests/art_density_debt.txt`. Крупный план — `gen: closeup` (план: `tools/art/closeup_plan.py`).
  Референсы персонажей в closeup не передавай: с `kuni-maid.png` gemini дорисовал колокольчик на чокер в ch1, где
  его ещё нет; без них кусок перерисовывается точно.
- **После душа и ночью Куня в рубашке, не в форме** (таблица в `docs/characters/kuni/README.md`, «Одежда по сценам»):
  кадр с мокрыми волосами и полотенцем в форме = баг (стр.117–119).
- **Масштаб.** Бенгальский кот — обычный домашний кот: длина тела примерно четверть ширины кровати; gemini рисует его
  размером с кровать (`inv3/cat_sees`). Пиши в промпте «SCALE: body length about one quarter of the bed's width» и
  смотри кадр.
- **Предмет «в воздухе».** «Висит в воздухе» gemini рисует как провод, свисающий со стола (`inv3/cable_air`). Работает
  так: провод идёт от розетки, а свободный конец с вилкой плывёт посреди комнаты, вокруг пустой воздух и на нём блик.
- **Местоимение «он» после предмета — это предмет.** «Провод так и висит в воздухе. Он встаёт.»: читатель принимает «он»
  за провод. После существительного м. р. (провод, кот, телефон) называй человека. Охраняет `TextLint.HeAfterAMasculineThingNamesThePerson`.
- **Слова из доков не попадают в текст игры** («в сне это канон»). Охраняет `TextLint.NoDesignDocWordsInTheText`.
- **Ушедший не остаётся в кадре.** «Кот уходит» (`ch2/Dare`), а следующая панель — та же `group` с котом на полке.
  Картинки, где нарисован кот, помечены `- has: cat`; после реплики «кот уходит/убегает» в той же ветке нужна
  картинка без него (`group_nocat` = `edit group` «убери кота с полки»). То же правило для любого уходящего, исчезающего
  или убранного предмета: после текста о нём кадр без него. Охраняет `NoCatInPanelsAfterTheCatLeft`; для другого
  существа добавь регэксп в тест и `- has:` в доке картинки.

- **Время суток задаёт текст, арт подстраивается.** «Утро» на странице, а за окном сумерки (`ch3/scold` на стр.77 после
  утреннего завтрака) читатель принимает за ошибку, а не за ход. Если сцена идёт из утра в вечер, переход проговаривает
  текст («вечером», «к ночи», часы на экране). У картинки с окном или светом ставь `- time:`, в промпте пиши время
  суток словами и запрещай чужое («pale morning daylight, no sunset glow, no dusk, candles not lit»). Дождь и погода
  работают так же. Охраняет `LightChangesOnlyAfterTextThatSaysSo`: между двумя кадрами с `- time:` из разных половин
  суток (светло/темно) в файле сцены должна быть реплика с маркером («вечером», «ночью», «рассвело», `19:20`…).
  `TimeOfDayInTextMatchesItsPicture`: подпись, которая начинается со времени («Ночью…»), предложение-время («Серый
  пасмурный вечер.», «Мост. Вечер.») и приветствие («Доброе утро», «Спокойной ночи») стоят на картинке того же света
  (или следующая картинка его). Тесты видят только картинки с `- time:`, поэтому он обязателен у всех
  (`EveryUsedPictureSaysItsTimeOfDay`).

**Как работать:**

- **Варианты выбирает автор.** Делай 3–4 варианта в scratchpad, собирай их в одну подписанную картинку
  (`magick montage -label '%t' v1.png v2.png … -tile 2x2`) и прикладывай крупный кроп спорной детали (клава, пальцы,
  часы). Коротко опиши каждый вариант (что хорошо, что плохо) и скажи, какой взял бы ты, но решает автор. В игру
  кладётся только выбранный вариант.
- **Превью SDXL делай с `--hr`**, как в `generate.py`. Без hires превью выглядит иначе: в `hands` пальцы были
  нормальными в превью и сломались в финале с тем же сидом.
- **Из SDXL пробуй 4 сида за раз** (`-n 4`). Если два захода по четыре не дали годной картинки, значит SDXL этого не
  умеет: переходи на `edit`/`ref` в gemini, а не крути промпт дальше.
- **Чтобы исправить деталь на принятой картинке** (часы, клава), правь её саму (`edit <id>_clean`) и передай в
  `refs` картинку, где эта деталь уже правильная: «make his wristwatch exactly the same silver steel watch as in the
  second image», «replace the keyboard with exactly the same keyboard as in the second image». Перечисли, что должно
  остаться как есть (поза, лицо, кот, мышь, мониторы), иначе gemini перерисует и это.
- **После правки проверь разметку**: сдвинулось ли то, что размечено (`screen`, `avoid`, точки голов). Экран меряй по
  пикселям, а не на глаз, и посмотри результат в игре через aui-remote: текст терминала должен лечь ровно в рамку.
- **`avoid` лица — до подбородка**, а не до глаз. В `room` бокс кончался на глазах, и движок положил подпись
  на рот и подбородок. Бокс берёт всю голову: от макушки до подбородка, от уха до кончиков чёлки. Точка головы —
  середина лица (между глазами и ртом), а не макушка. Проверяй разметку, рисуя боксы и точки поверх картинки
  (PIL, `ImageDraw.rectangle`) и глядя на результат, а не по цифрам.
- **Перед генерацией по id сделай бэкап.** `data/img` не в git, перегенерированную картинку не вернуть. Скопируй в
  scratchpad саму картинку и её `refs`/`source`. Раньше `generate.py` молча пересоздавал устаревшие референсы
  (так при переделке `clock` перерисовались `room_base` и `room`, и старая комната пропала). Теперь он
  берёт устаревший референс как есть и пишет warning, а создаёт только отсутствующие. Устаревшее по `--list` не
  значит, что картинку надо перегенерировать: может, просто поменялся `define`.
- **Перегенерация задевает соседние кадры.** Прежде чем перегенерировать картинку, найди, у кого она в `refs`
  (`grep -n '^- refs:.*<id>' docs/art/*.md`), и согласуй с автором, переделывать ли и их. После перегенерации
  `--list` пометит такие картинки как `remade after it: …`.

## Опыт: то, что модель не умеет, считаем сами (дверь на петлях, онкомопеи)

Урок `wr_slam` / `ai2_door_slam` (пролог). Четыре раунда промптов «дверь захлопывается, призраки смаза» давали: призраки
под углом, потом плоская дверь, «которая едет вбок, как в метро», потом створка, «выпавшая из петель». Модель
не держит геометрию вращения, сколько ни описывай. Сработало разделение труда:

- **Геометрию считаем сами, модель только украшает.** `tools/art/hinged_door.py` берёт створку с ручкой автора
  (`wr_door`) и поворачивает её вокруг петельного края в трёх фазах (20/45/70°): петельная кромка вертикальна и
  неподвижна, свободная уходит к зрителю и становится выше (`s = Z0 / (Z0 − w·sin θ)`), каждая фаза — обычный
  perspective transform Pillow по четырём точкам. Главная створка непрозрачна, призраки 42% и 30%. Это тот же лист на
  разных углах, а не копии, поэтому из петель он выпасть не может. Для кадра с девочкой её вырезаем по компоненте
  связности (волосы + контур, дыры залиты) и кладём поверх створки: она стоит ближе к зрителю. Скрипт ничего не
  рисует «от руки», Blender не нужен.
- **Потом модель (`edit` по такой сборке).** Промпт: «keep this image EXACTLY as it is, the leaf and its ghosts are
  positioned precisely, do NOT move, redraw or reshape them; ONLY ADD speed lines behind the door, dust puffs, impact
  marks (and hair tips / hem blown back)». Просить «убери зелёные/пурпурные направляющие» не нужно: мы направляющие
  на картинку не кладём (пробовали, модель рисует по ним криво, дверь получалась на неправильном месте).
- **Просить «no text, no letters, no katakana».** Иначе gemini сам дорисовывает «バァァーン» мазками. Движок рисует
  звуки сам, дубли не нужны.
- **Не дописывай модели то, что можно посчитать:** перспектива, повторы, смещения, маски. Варианты генерируй 4 штуки
  сразу, выбирает автор по коллажу.

**Онкомопеи** (`data/img/onomatopoeia/<слово>_<n>.webp`, русские слова): рисует gemini отдельными картинками («single
large hand-lettered manga sound-effect word in CYRILLIC capital letters, black ink on pure white, nothing else: no
speed lines, no background, no frame»). Слово пиши в «...» точно, иначе в буквах ошибки; кавычки модель иногда
дорисовывает сама. Движок кладёт их в кадр через MULTIPLY (`kn::ImageCache::multiplyKey`: чёрные чернила с альфой = темнота пикселя),
поэтому белый фон не нужно вырезать. Новое слово = два варианта файла + строка в таблице в
`GameView::onomatopoeiaKey`. Английские (`en_<word>_<n>.webp`, LATIN capital letters) — для перевода этих же слов из
`data/lang/en.txt`: таблица ищет по уже переведённому тексту; без референса на кириллицу, иначе модель пишет кириллицей.
