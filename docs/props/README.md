# Предметы: канонические референсы

Сквозные предметы, которые появляются на многих панелях, получают канон так же, как персонажи и места: README с
устройством предмета и картинку-референс. Любая панель с предметом передаёт картинку в `refs` и в промпте прямо
называет, что должно совпасть.

Почему: в I love Kuni Оракула сначала нарисовали под стеклянным куполом, а по сюжету в него суют бумажки и дёргают
рычаг — сквозь стекло так нельзя. Плюс сбоку была щель неясного назначения (читалась как монетоприёмник). Предмет
без канона каждая панель додумывает по-своему.

| Предмет | README | Референс |
| --- | --- | --- |
| Оракул (латунный автомат на тумбе, пример, CC BY-NC-SA 4.0) | [`oracle/`](oracle/README.md) | `oracle.webp` |
| `<твой предмет>` | | |

## Формат README предмета

1. **Что это.**
2. **Устройство:** из чего состоит, сколько у него отверстий/кнопок/ламп и для чего каждое. Каждая деталь, которой
   пользуются персонажи, **физически доступна** (не под стеклом, не внутри) и имеет понятное назначение. Деталей
   «просто так», похожих на функциональные (щели, кнопки, замочные скважины), нет.
3. **Как им пользуются** — по шагам, чтобы панели «до/во время/после» сходились.
4. **Чего на картинках быть не должно.**

## Картинки

`<предмет>.webp`, 832×1216, предмет целиком, ¾ спереди, на нейтральном сером фоне, без людей и текста. Делаются и
правятся только через генератор с референсами (`openrouter-image`). Поменять референс = поменять предмет на всех
панелях: `grep -rn 'docs/props/<предмет>' docs/art/`.
